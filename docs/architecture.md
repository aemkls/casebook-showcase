# Архитектура

## Данные

Каждый раздел — это пара артефактов, которые целиком загружаются в браузер:

- `offline-payload.b64` — gzip + base64 с JSON: метаданные, краткие карточки дел, поисковые префиксы слов, сводные частоты формулировок;
- `source-bundles/<xx>.json.gz` — полные тексты, сгруппированные по первым двум символам идентификатора. Браузер скачивает только тот пакет, в котором лежит открываемое дело.

Строка карточки — массив полей: идентификатор, дата, номер дела, суд, тема, подтема, требования, исход, уверенность разметки, фрагменты, поисковые токены, вид акта, ссылка на повтор, вид наказания (для уголовных дел).

## Разметка

Правила намеренно привязаны к конкретным местам документа, а не к словам по всему тексту:

- **Уголовные дела:** категория — по статье Особенной части в формулировке обвинения и резолютивной части (а не по ранее упомянутым судимостям); исход и вид наказания — по резолютивной части.
- **Гражданские дела:** тема — по блоку требований истца; исход — по резолютивной части; для апелляции — оставлено без изменения, отменено или изменено.
- **Обстоятельства:** список регулярных выражений по мотивировочной части, подсчёт по исходам.

Разметка автоматическая; поле уверенности относится к сработавшему правилу.

## Обезличивание

Конвейер из нескольких слоёв: правила («Фамилия И.О.», полные ФИО, слова после процессуальных ролей), модель Natasha NER и словарь pymorphy3 для отсечения обычных слов и топонимов. Каждый человек получает номер ФИО-N по первому появлению в документе; ИИН и адреса проживания скрываются, даты рождения сокращаются до года. Проверка `validate_data.py` ищет оставшиеся имена и ИИН в опубликованных текстах.

## Интерфейс

Одна страница без фреймворков. Поиск выполняется в Web Worker: лексический, по пятисимвольным префиксам слов с весами по редкости, плюс определение темы по словарю. Разделы описываются конфигурацией `SECTIONS`, поэтому новый раздел добавляется данными и текстами, без новой логики.
